# 저장소 자동화 루틴

이 저장소에는 두 개의 일일 자동화 루틴이 있습니다.

| 루틴 | 실행 시각(KST) | 스크립트 |
|---|---|---|
| 미국 3대 지수 종가 기록 | 오전 5시 (월~금) | `scripts/fetch_indices.py` |
| 엔에이치아문디 ETF 상관계수 위반 공시 체크 | 오전 10시 (월~금) | `scripts/check_etf_correlation.py` |

---

## 미국 증시 종가 기록 루틴 (나스닥 · S&P 500 · 다우)

매일 아침(한국시간 기준) 미국 3대 지수의 **종가를 자동으로 기록**하는 루틴입니다.

- **나스닥 종합지수** (Nasdaq Composite, `.IXIC` / `^IXIC`)
- **S&P 500** (`.SPX` / `^GSPC`)
- **다우존스 산업평균지수** (Dow Jones Industrial Average, `.DJI` / `^DJI`)

수집한 값은 저장소의 `data/` 폴더에 누적 저장됩니다.

---

## 동작 방식

1. **스케줄러**: Claude 원격 루틴(Routine)이 매일 정해진 시각에 새 Claude 세션을 깨웁니다.
2. **수집**: 그 세션이 `scripts/fetch_indices.py`를 실행합니다.
   - 기본 소스: **CNBC** (한 번의 요청으로 세 지수 + 시장상태 + 전일종가)
   - 백업 소스: **Yahoo Finance** (CNBC 실패 시 지수별로 조회)
   - 둘 다 API 키가 필요 없고, 파이썬 표준 라이브러리만 사용합니다.
3. **기록**: `data/index_closes.csv`에 지수별로 한 줄씩 append 하고, `data/latest.json`을 최신 값으로 갱신합니다.
4. **커밋**: 세션이 변경분을 커밋하고 브랜치에 push 합니다.

## 실행 시각 ⏰

- **한국시간(KST) 오전 5시**에 실행합니다. → cron `0 20 * * 1-5` (UTC 20:00, 월~금)
- UTC 월~금 20:00 = KST 화~토 오전 5시로, **미국 정규장 5거래일의 종가를 각각 다음 날 아침에** 기록합니다. (주말은 새 종가가 없으므로 실행하지 않습니다.)

> ⚠️ **서머타임 주의**
> 미국 증시는 뉴욕시간 오후 4시에 마감합니다.
> - **미국 여름(서머타임, 대략 3~11월)**: 마감 = KST 오전 5시 → 5시 기록이 곧 **확정 종가**입니다. ✅
> - **미국 겨울(대략 11~3월)**: 마감 = KST 오전 6시 → KST 5시엔 **아직 장중**이라, 이때 기록되는 값은 마감 약 1시간 전의 장중 가격입니다.
>
> 그래서 각 행에는 `market_time_et`(가격 시각)와 `market_status`(시장 상태) 컬럼이 함께 저장됩니다. 값이 확정 종가인지 장중 스냅샷인지 항상 구분할 수 있습니다.
> 겨울에도 확정 종가만 남기고 싶다면 아래 "실행 시각 변경"을 참고해 KST 오전 7시(UTC 22:00)로 바꾸세요.

## 수동 실행 / 테스트

```bash
python3 scripts/fetch_indices.py
```

의존성 설치가 필요 없습니다. 실행하면 `data/`에 값이 추가됩니다.

## 실행 시각 변경

루틴의 cron 식을 바꾸면 됩니다 (UTC 기준). 참고 매핑:

| 원하는 KST 시각 | cron (UTC) | 비고 |
|---|---|---|
| 오전 5시 (현재) | `0 20 * * 1-5` | 여름=확정 종가 / 겨울=장중 |
| 오전 6시 | `0 21 * * 1-5` | 겨울 마감 시각 |
| 오전 7시 | `0 22 * * 1-5` | 사계절 확정 종가 (권장) |
| 매일(주말 포함) | `0 20 * * *` | 주말은 금요일 종가가 반복 기록됨 |

Claude에게 "루틴 실행 시각을 KST 오전 7시로 바꿔줘"처럼 말하면 변경해 드립니다.

# 엔에이치아문디 ETF 상관계수 위반 공시 체크 📌

**엔에이치아문디자산운용(HANARO) ETF** 중 그날 **상관계수 미달(위반) 공시**가 뜬 종목이 있는지 확인합니다.

- 한국거래소는 ETF의 기초지수와 NAV 간 **상관계수가 0.9에 미달**하면 "ETF 상관계수 미달 발생" 공시를, 회복되면 "해소" 공시를 냅니다.
- **당일자 공시만** 확인합니다. 과거 데이터는 조회하지 않습니다.
- 공시는 보통 오전 9시 30분까지 마무리되므로 **KST 오전 10시**(cron `0 1 * * 1-5`, UTC 01:00 월~금)에 실행합니다.

## 동작 방식

1. **1순위 — KIND ETF 공시 목록**(`disclosurebystocktype.do`, 최신순)을 한 번의 요청으로 읽어 엔에이치아문디 건만 추립니다.
2. **폴백 — 네이버 증권**: KIND가 막혀 있으면 `HANARO`로 시작하는 ETF(현재 50종목)의 당일 공시를 훑습니다. (목록 제목이 잘려 나오므로 당일 행만 상세 페이지를 열어 전체 제목을 읽습니다.)
3. 제목을 분류합니다.
   - `violation` — 제목에 **상관계수**가 있고 해소/해제가 아닌 경우 → 🚨 위반
   - `resolved` — **상관계수 … 해소**
   - `related` — 괴리율 초과 / 추적오차 / 자산구성내역 오류 / 지수 산출 중단 등 참고 유형
   - 분배락·LP 변경 등 무관한 공시는 제외
4. **패시브/액티브를 구분**합니다. 액티브 ETF는 거래소 규정상 종목명에 `액티브`가 반드시 들어가므로 이름으로 판정합니다.
   - 패시브(지수추종): 상관계수 **0.9** 미만이면 미달
   - 액티브: 상관계수 **0.7** 미만이면 미달
5. 위반 건은 **연속 영업일 수**와 **달력일 경과/3개월 요건**을 함께 계산합니다 (아래 참고).
6. 결과를 `data/`에 기록하고 커밋합니다.

## 연속 영업일 카운트 📈

같은 종목의 상관계수 미달이 **끊기지 않고 며칠째 이어지는지**를 셉니다.

- **중간에 한 번이라도 "위반 없음"으로 확인된 날이 끼면 카운트는 1부터 다시 시작합니다.** 상관계수가 회복되면 상장폐지 사유가 사라지므로, 불연속 구간은 이어 붙이지 않습니다.
- "영업일"의 기준은 달력이 아니라 **이 스크립트가 실제로 확인한 날짜**입니다. 주말·공휴일이나 루틴이 돌지 않은 날은 그냥 건너뛰며, 연속을 끊지 않습니다.
- 카운트는 **최신 날짜에서 과거로 거꾸로** 셉니다. 위반이 없던 날을 만나는 순간 멈추므로, 항상 "지금 이어지고 있는 구간"만 세고 그보다 앞선 별개의 위반 구간은 합산하지 않습니다.
- **3개월 요건은 영업일이 아니라 달력일 기준**입니다. 그래서 위반 시작일 기준 경과 달력일(`calendar_days`)과 3개월 도달일(`deadline_3m`, 말일 보정 포함), 남은 달력일(`days_to_3m`)을 함께 계산해 도달 시 ⚠️ 로 표시합니다. (상관계수 미달이 3개월 지속되면 관리종목 지정 사유)
- 결과는 아래처럼 나오고,

```
🚨 [293180] HANARO 200 [패시브·기준 0.9] — 67영업일째 (최초 2026-05-27)
      달력 93일 경과 / 3개월 요건 ⚠️ 도달 (2026-08-27)
```
 CSV에는 `streak_days` / `streak_since` 컬럼으로 남습니다.

> ℹ️ **데이터 출처**: 원본은 거래소 KIND 공시입니다. 다만 이 실행 환경에서는 `kind.krx.co.kr`이 403으로 차단되어 있어
> KIND 응답을 실제로 확인하지 못했고, 실패 시 **네이버 증권 종목 공시**(같은 거래소·코스콤 피드를 중계)로 자동 전환됩니다.
> KIND가 열려 있는 사내망에서는 `--source kind`로 원본 경로만 쓸 수 있습니다. 어느 쪽이든 API 키는 필요 없습니다.

## 데이터 형식

`data/etf_correlation_checks.csv`

| 컬럼 | 설명 |
|---|---|
| `checked_kst` | 확인 실행 시각(KST) |
| `check_date` | 확인 대상 날짜 |
| `status` | `violation` / `resolved` / `related` / `none` |
| `ticker` / `etf_name` | 종목코드 / ETF 이름 |
| `title` | 공시 전체 제목 |
| `disclosure_date` | 공시일 |
| `url` | 공시 원문 링크 |
| `etf_type` | `passive` / `active` |
| `threshold` | 해당 유형의 상관계수 기준 (0.9 / 0.7) |
| `calendar_days` | 위반 시작일부터 경과한 **달력일** |
| `deadline_3m` | 3개월(달력) 도달일 |
| `days_to_3m` | 도달까지 남은 달력일 (0 이하면 도달) |
| `streak_days` | 위반이 연속된 영업일 수 (오늘 포함) |
| `streak_since` | 그 연속 구간이 시작된 날짜 |
| `manager` | 운용사 (엔에이치아문디자산운용) |

상관계수 공시가 하나도 없던 날도 `status=none` 한 줄로 남겨, "확인은 했고 위반이 없었다"는 사실이 기록됩니다.
`data/etf_correlation_latest.json`에는 가장 최근 실행 결과 전체가 들어갑니다.

## 수동 실행 / 테스트

```bash
python3 scripts/check_etf_correlation.py                 # 오늘(KST) 확인 후 기록
python3 scripts/check_etf_correlation.py --no-write       # 기록 없이 출력만
python3 scripts/check_etf_correlation.py --date 2026-06-24 --no-write   # 특정일 확인
python3 scripts/check_etf_correlation.py --source kind                    # KIND만 사용 (사내망)
```

의존성 설치가 필요 없습니다(파이썬 표준 라이브러리만 사용).
