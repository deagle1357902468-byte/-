# 저장소 자동화 루틴

이 저장소에는 두 개의 일일 자동화 루틴이 있습니다.

| 루틴 | 실행 시각(KST) | 스크립트 |
|---|---|---|
| 미국 3대 지수 종가 기록 | 오전 5시 (월~금) | `scripts/fetch_indices.py` |
| 엔에이치아문디 ETF 상관계수 위반 공시 체크 | 오전 11시 10분 (월~금) | `scripts/check_etf_correlation.py` |

---

## 미국 증시 종가 기록 루틴 (나스닥 · S&P 500 · 다우)

매일 아침(한국시간 기준) 미국 3대 지수의 **종가를 자동으로 기록**하는 루틴입니다.

- **나스닥 종합지수** (Nasdaq Composite, `.IXIC` / `^IXIC`)
- **S&P 500** (`.SPX` / `^GSPC`)
- **다우존스 산업평균지수** (Dow Jones Industrial Average, `.DJI` / `^DJI`)

수집한 값은 저장소의 `data/` 폴더에 누적 저장됩니다.

---

## 동작 방식

1. **스케줄러**: Claude 원격 루틴(Routine)이 매일 정해진 시각에 새 Claude 세션을 깨웁니다.
2. **수집**: 그 세션이 `scripts/fetch_indices.py`를 실행합니다.
   - 기본 소스: **CNBC** (한 번의 요청으로 세 지수 + 시장상태 + 전일종가)
   - 백업 소스: **Yahoo Finance** (CNBC 실패 시 지수별로 조회)
   - 둘 다 API 키가 필요 없고, 파이썬 표준 라이브러리만 사용합니다.
3. **기록**: `data/index_closes.csv`에 지수별로 한 줄씩 append 하고, `data/latest.json`을 최신 값으로 갱신합니다.
4. **커밋**: 세션이 변경분을 커밋하고 브랜치에 push 합니다.

## 실행 시각 ⏰

- **한국시간(KST) 오전 5시**에 실행합니다. → cron `0 20 * * 1-5` (UTC 20:00, 월~금)
- UTC 월~금 20:00 = KST 화~토 오전 5시로, **미국 정규장 5거래일의 종가를 각각 다음 날 아침에** 기록합니다. (주말은 새 종가가 없으므로 실행하지 않습니다.)

> ⚠️ **서머타임 주의**
> 미국 증시는 뉴욕시간 오후 4시에 마감합니다.
> - **미국 여름(서머타임, 대략 3~11월)**: 마감 = KST 오전 5시 → 5시 기록이 곧 **확정 종가**입니다. ✅
> - **미국 겨울(대략 11~3월)**: 마감 = KST 오전 6시 → KST 5시엔 **아직 장중**이라, 이때 기록되는 값은 마감 약 1시간 전의 장중 가격입니다.
>
> 그래서 각 행에는 `market_time_et`(가격 시각)와 `market_status`(시장 상태) 컬럼이 함께 저장됩니다. 값이 확정 종가인지 장중 스냅샷인지 항상 구분할 수 있습니다.
> 겨울에도 확정 종가만 남기고 싶다면 아래 "실행 시각 변경"을 참고해 KST 오전 7시(UTC 22:00)로 바꾸세요.

# 엔에이치아문디 ETF 상관계수 위반 공시 체크 📌

**엔에이치아문디자산운용(HANARO) ETF** 중 그날 **상관계수 미달(위반) 공시**가 뜬 종목이 있는지 확인합니다.

- 한국거래소는 ETF의 기초지수와 NAV 간 상관계수가 기준(**패시브 0.9 / 액티브 0.7**)에 미달하면 "**ETF 상관계수 기준 미달 발생**" 공시를, 회복되면 해소 공시를 냅니다.
- **당일자 공시만** 확인합니다. 과거 데이터는 조회하지 않습니다.
- **KST 오전 11시 10분**(cron `10 2 * * 1-5`, UTC 02:10 월~금)에 실행합니다.
  처음에는 오전 10시에 돌렸는데, 2026-09-01 HANARO 미국S&P500액티브 건이 **10시 30분경 접수**되어
  그날 스냅샷에서 빠졌습니다. 늦게 올라오는 공시를 같은 날 잡으려고 시각을 늦췄습니다.

## 동작 방식

1. **KIND ETF 공시 목록**(`disclosurebystocktype.do`)을 **당일 날짜로 한 번** 요청해 읽고, **제출인 = 엔에이치아문디자산운용** 건만 추립니다.
2. **폴백 — 네이버 증권**: KIND가 응답하지 않으면 `HANARO`로 시작하는 ETF(현재 50종목)의 당일 공시를 훑습니다. (목록 제목이 잘려 나오므로 당일 행만 상세 페이지를 열어 전체 제목을 읽습니다.)
3. 제목을 분류합니다.
   - `violation` — 제목에 **상관계수**가 있고 해소/해제가 아닌 경우 → 🚨 위반 (실제 문구: `ETF 상관계수 기준 미달 발생`)
   - `resolved` — **상관계수 … 해소**
   - `related` — 괴리율 초과 / 추적오차 / 자산구성내역 오류 / 지수 산출 중단 등 참고 유형
   - 분배락·LP 변경 등 무관한 공시는 제외
4. **패시브/액티브를 구분**합니다. 액티브 ETF는 거래소 규정상 종목명에 `액티브`가 반드시 들어가므로 이름으로 판정합니다.
   - 패시브(지수추종): 상관계수 **0.9** 미만이면 미달
   - 액티브: 상관계수 **0.7** 미만이면 미달
5. 위반 건은 **연속 영업일 수**와 **달력일 경과/3개월 요건**을 함께 계산합니다 (아래 참고).
6. 결과를 `data/`에 기록하고 커밋합니다.

## 연속 영업일 카운트 📈

같은 종목의 상관계수 미달이 **끊기지 않고 며칠째 이어지는지**를 셉니다.

- **중간에 한 번이라도 "위반 없음"으로 확인된 날이 끼면 카운트는 1부터 다시 시작합니다.** 상관계수가 회복되면 상장폐지 사유가 사라지므로, 불연속 구간은 이어 붙이지 않습니다.
- "영업일"의 기준은 달력이 아니라 **이 스크립트가 실제로 확인한 날짜**입니다. 주말·공휴일이나 루틴이 돌지 않은 날은 그냥 건너뛰며, 연속을 끊지 않습니다.
- 우리 CSV에 기록이 없는 구간(첫 실행 등)은 **공시 이력 자체를 과거로 훑어** 시작일을 잡습니다. 피드에는 "위반이 없던 날"이 남지 않으므로, 위반 공시 사이 간격이 4일(주말+공휴일) 이내면 이어진 것으로 봅니다.
- 카운트는 **최신 날짜에서 과거로 거꾸로** 셉니다. 위반이 없던 날을 만나는 순간 멈추므로, 항상 "지금 이어지고 있는 구간"만 세고 그보다 앞선 별개의 위반 구간은 합산하지 않습니다.
- **우리 기록과 공시 이력이 엇갈리면 공시 이력이 이깁니다.** 우리 기록은 하루 전체가 아니라 루틴이 도는 시각의 스냅샷이라, 그 뒤에 접수된 공시가 빠져 있을 수 있습니다. 그 빈 자리를 "위반 없음"으로 읽으면 다음 날 연속일이 1로 리셋돼 3개월 요건을 실제보다 늦게 잡습니다. (2026-09-01 HANARO 미국S&P500액티브 건이 10시 30분경 접수돼 그날 10시 스냅샷에서 빠졌고, 다음 날 "오늘 최초"로 잘못 계산됐습니다. 실행 시각을 11시 10분으로 늦추고 이 우선순위를 도입해 바로잡았습니다.)
- **3개월 요건은 영업일이 아니라 달력일 기준**입니다. 그래서 위반 시작일 기준 경과 달력일(`calendar_days`)과 3개월 도달일(`deadline_3m`, 말일 보정 포함), 남은 달력일(`days_to_3m`)을 함께 계산해 도달 시 ⚠️ 로 표시합니다. (상관계수 미달이 3개월 지속되면 관리종목 지정 사유)
- 결과는 아래처럼 나오고,

```
🚨 [293180] HANARO 200 [패시브·기준 0.9] — 67영업일째 (최초 2026-05-27)
      달력 93일 경과 / 3개월 요건 ⚠️ 도달 (2026-08-27)
```
 CSV에는 `streak_days` / `streak_since` 컬럼으로 남습니다.

> ℹ️ **데이터 출처**: 거래소 **KIND 원본**을 씁니다. 당일 날짜로 한 번 요청하면 끝나고, 연속 일수 계산에 필요한
> 과거 이력도 KIND의 날짜범위 검색으로 가져옵니다. KIND가 응답하지 않을 때만 네이버 증권 공시(같은 거래소·코스콤
> 피드를 중계)로 자동 전환됩니다. API 키는 필요 없습니다.
>
> ⚠️ KIND는 클라이언트를 가려서 차단합니다. **curl로는 403**이 떨어지지만 이 스크립트(파이썬 urllib)는 정상 응답을
> 받습니다. 디버깅할 때 curl 결과만 보고 "막혔다"고 판단하지 마세요.

## 수동 실행 / 테스트

```bash
python3 scripts/check_etf_correlation.py                 # 오늘(KST) 확인 후 기록
python3 scripts/check_etf_correlation.py --no-write       # 기록 없이 출력만
python3 scripts/check_etf_correlation.py --notify         # 알림 본문만 출력 (루틴이 쓰는 모드)
python3 scripts/check_etf_correlation.py --date 2026-06-24 --no-write   # 특정일 확인
python3 scripts/check_etf_correlation.py --source kind                    # KIND만 사용 (사내망)
```

의존성 설치가 필요 없습니다(파이썬 표준 라이브러리만 사용).

## 알림 형식 🔔

루틴은 `--notify` 로 실행합니다. 이 모드의 **stdout에는 알림 본문만** 담기고, 진행 메시지와
기록 결과는 stderr로 나갑니다. 알릴 것이 없는 날(위반도 해소도 없음)에는 **아무것도 출력하지
않으므로**, 출력이 비었으면 알림을 보내지 않으면 됩니다.

```
🚨 08-31 위반 19영업일째 · 3개월 요건까지 64일 — HANARO 글로벌피지컬AI액티브 (0040S0)

     2026-08-31 (KST) 기준

     상태  ⛔ 위반 지속 중
     연속  19영업일  (2026-08-03 최초)
     달력  29일 경과 → 마감 2026-11-03
     여유  64일  ██████░░░░░░░░░░░░░░

     ETF 상관계수 기준 미달 발생 · 액티브 기준 0.7

     ─────────────────────────
     참고 · 0215T0 HANARO 미국AI광통신TOP10 ETF 괴리율 초과 발생
```

형식을 이렇게 잡은 이유:

- **첫 줄에 결론을 다 담습니다.** 폰 배너는 첫 문장만 보여주고 나머지를 자르므로, 날짜·연속일·남은 기한·종목이 한 줄에 들어가야 알림만 보고 판단할 수 있습니다. 배너 자리를 아끼려고 날짜는 `MM-DD`로 줄이고, 전체 날짜는 본문에 다시 적습니다.
- **막대는 블록문자(`█░`)입니다.** 알림·메일은 고정폭 폰트가 보장되지 않아 `┌─┐` 같은 표나 열 맞춤은 폰에서 어긋납니다. 블록문자는 안 깨집니다.
- **공시 주소는 넣지 않습니다.** 받는 앱이 알림 텍스트에 자동 링크를 걸어주지 않아, 클릭도 안 되는 80자짜리 문자열이 본문만 차지합니다. 주소는 `data/etf_correlation_latest.json` 의 `url` 에 그대로 있습니다.
- **아이콘이 상태를 나타냅니다.** 평시 🚨 / 3개월 요건까지 30일 이하면 `(기한 임박)` / 도달하면 ⛔.

## 사내 PC에서 KIND 원본으로 실행하기 🖥️

원격 루틴에서도 KIND 원본이 정상 동작하므로 **필수는 아닙니다.** 다만 사내 PC에서 직접 돌리고 싶을 때,
또는 결과를 로컬에 쌓아두고 싶을 때 쓰라고 준비해 둔 실행 파일입니다.

### 1. 준비 (최초 1회)
1. [파이썬](https://www.python.org/downloads/) 설치 — 설치 화면에서 **"Add python.exe to PATH" 체크 필수**.
2. 이 저장소를 내려받아 아무 폴더에 풀어 둡니다. (GitHub 페이지 → Code → Download ZIP)

### 2. 실행
`scripts\run_kind.bat` 을 **더블클릭**하면 됩니다. 결과가 창에 뜨고, 파일에도 기록됩니다.

| 경로 | 내용 |
|---|---|
| `data\etf_correlation_checks.csv` | 실행 기록 누적 (연속 일수 계산의 근거) |
| `data\etf_correlation_latest.json` | 가장 최근 결과 |
| `logs\YYYYMMDD.log` | 그날 실행 화면 그대로 |

명령창에서 직접 돌리려면:
```
python scripts\check_etf_correlation.py --source kind
```

### 3. 매일 오전 11시 10분 자동 실행 (작업 스케줄러)
명령 프롬프트를 **관리자 권한으로** 열고, 아래 한 줄을 실행하세요 (경로는 실제 위치로 바꿔서):

```
schtasks /create /tn "ETF 상관계수 체크" /tr "\"C:\경로\scripts\run_kind.bat\"" /sc weekly /d MON,TUE,WED,THU,FRI /st 11:10
```

등록 확인·삭제:
```
schtasks /query /tn "ETF 상관계수 체크"
schtasks /delete /tn "ETF 상관계수 체크" /f
```

> 💡 **CSV를 계속 같은 폴더에 쌓아 두세요.** 연속 영업일 카운트가 이 기록을 근거로 삼습니다.
> (기록이 없으면 공시 이력을 거꾸로 훑어 시작일을 추정하지만, 실행 기록이 있는 쪽이 정확합니다.)
